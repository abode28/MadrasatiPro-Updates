مدرستي Pro — بدء التحديث التلقائي
=================================

ما الذي أُضيف؟
- تحسينات إضافية للواجهة والخطوط والعناوين والأيقونات وتباين لوحة المؤشرات في الوضعين الفاتح والداكن.
- زر «تحديث البرنامج» داخل التطبيق.
- فحص تلقائي عند بدء التطبيق، مع فحص يدوي من الزر.
- تنزيل مُثبّت Windows من الإصدار المنشور والتحقق من SHA-256 قبل تشغيله.
- مسار GitHub Actions لبناء ملف التثبيت ونشره في GitHub Releases.

الإعداد الأول (مرة واحدة فقط)
------------------------------
1. تحتاج إلى مستودع GitHub عام لنشر ملفات التحديث. لا ترفع إليه قاعدة بيانات مدرسة أو أي بيانات حقيقية للطلبة.
2. ارفع ملفات هذا المشروع كاملة إلى المستودع، مع المجلد المخفي .github ومجلد scripts.
3. افتح Actions في GitHub وفعّل سير العمل إن طلب GitHub ذلك.
4. شغّل سير العمل: Build and publish Madrasati Pro update، واستخدم الإصدار 1.1.0 للإصدار الأول.
5. بعد نجاح البناء، ستجد في صفحة Releases ملف SchoolManagerPro_Setup_1.1.0.exe وملف SHA-256 المرافق له.
6. نزّل المُثبّت وشغّله مرة واحدة على الأجهزة التي عليها نسخة قديمة. هذه هي خطوة التهيئة الوحيدة للنسخ القديمة التي لا تحتوي على آلية تحديث.

كل تحديث لاحق
-------------
1. ارفع تعديلات كود البرنامج إلى المستودع نفسه.
2. من GitHub > Actions شغّل سير العمل نفسه، لكن استخدم رقماً أعلى، مثلاً 1.1.1 ثم 1.1.2.
3. يتعرف البرنامج المثبّت على الإصدار الجديد عند تشغيله أو عند ضغط «تحديث البرنامج»، وينزّله ويتحقق منه ثم يبدأ التثبيت.
4. قد يطلب Windows موافقة المسؤول لتحديث التطبيق المثبّت في Program Files. تبقى ملفات بيانات المدرسة في مجلد بيانات المستخدم ولا يزيلها التحديث.

ملاحظات مهمة
-------------
- زر «تحديث البرنامج» في نسخة المدرسة يجلب آخر إصدار منشور؛ لا ينشر وحده تعديلات الكود الموجودة على حاسبة المطوّر.
- نشر إصدار جديد يتم عبر سير العمل المركزي على GitHub. لا حاجة بعد التهيئة إلى إرسال ZIP أو مطالبة كل مدرسة بفك الضغط.
- يجب أن يكون مستودع التحديث عاماً لأن النسخ المثبّتة لا تحمل رمز دخول إلى GitHub. إذا كنت لا تريد إظهار مصدر الكود علناً، فلا تنشره بهذا الأسلوب؛ يلزم خادم تحديث خاص بدلاً منه.
- تم فحص صياغة Python وتشغيل اختبارات قاعدة البيانات ومساعد التحديث بنجاح. بناء مُثبّت Windows النهائي واختباره يجب أن يتم على Windows/GitHub Actions.
