مدرستي Pro — نظام إدارة المدارس
================================
الإصدار: 1.1.0
نوع المنتج: تطبيق Windows مكتبي يعمل دون اتصال بالإنترنت

ما الذي يقدمه؟
---------------
- لوحة رئيسية بمؤشرات الطلاب والمدرسين والصفوف والغياب والوثائق.
- إدارة الصفوف والشعب، والمدرسين، والمواد، وبيانات الطلاب وأولياء الأمور.
- استيراد بيانات الطلاب من CSV وتصدير القوائم إلى CSV/Excel.
- تسجيل الحضور والغياب والتأخر والإجازات حسب الصف والتاريخ.
- الامتحانات والدرجات والنسب المئوية، وكشف درجات قابل للتصدير.
- جدول الحصص والمدرسين والقاعات وحساب أوقات الحصص من إعدادات الدوام.
- سجل الرسوم والأقساط والمدفوع والمتبقي بالدينار العراقي.
- أرشفة وثائق المدرسة والطلاب والمدرسين مع نسخ الملفات المرفقة داخل بيانات التطبيق.
- تقارير حضور وطلاب ومدرسين وجدول حصص ودرجات ورسوم.
- نسخة احتياطية كاملة ZIP تشمل قاعدة البيانات والوثائق، مع استعادة النسخة.
- تسجيل دخول محلي، إنشاء حساب مدير لأول تشغيل، إدارة الحسابات وتغيير كلمات المرور (التجزئة PBKDF2).
- واجهة عربية، شعار، أيقونة ويندوز، سجل أخطاء، وبيانات محفوظة محلياً.

تشغيل الكود في VS Code
----------------------
1. فك ضغط مشروع SchoolManagerProject.
2. افتح VS Code ثم File > Open Folder واختر مجلد المشروع.
3. افتح Terminal واكتب:
   python school_manager.py
4. لا يتطلب تشغيل التطبيق مكتبات Python خارجية. يلزم تثبيت Python مع Tkinter عند التطوير.

إنشاء نسخة Windows EXE والمُثبّت للمدارس
-----------------------------------------
المتطلبات: Windows 10/11 بنظام 64-bit، Python 3.11 أو 3.12، وInno Setup 6.
1. ثبّت Python من python.org وفعل خيار Add Python to PATH.
2. ثبّت Inno Setup 6 من موقعه الرسمي.
3. انقر مرتين على build_windows.bat.
4. سيُبنى التطبيق في dist\SchoolManagerPro\SchoolManagerPro.exe.
5. إذا كان Inno Setup مثبتاً، سيُنشأ المُثبّت في:
   dist-installer\SchoolManagerPro_Setup_1.1.0.exe
6. اختبر المُثبّت على حاسبة Windows نظيفة قبل توزيعه على أي مدرسة.

طريقة تثبيت البرنامج لدى المدرسة
---------------------------------
- أرسل للمدرسة ملف SchoolManagerPro_Setup_1.1.0.exe فقط بعد إتمام الاختبار.
- تفتح المدرسة المُثبّت، تكمل الخطوات، ثم تشغّل البرنامج من سطح المكتب أو قائمة Start.
- لا تحتاج حاسبة المدرسة إلى Python أو VS Code؛ فهما مطلوبان للبناء فقط، وليس لتشغيل المُثبّت الناتج.
- يجب بناء النسخة على Windows؛ ملف EXE النهائي لا يمكن اعتماده من فحص صياغة الكود على Linux وحده.

مكان حفظ البيانات
-----------------
على Windows تحفظ بيانات المستخدم في:
%LOCALAPPDATA%\SchoolManagerPro\SchoolData
ويشمل المجلد قاعدة البيانات school_manager.db والوثائق attachments والنسخ الاحتياطية backups والسجلات logs.
تظل البيانات موجودة عادة بعد تحديث البرنامج أو إلغاء تثبيته؛ المُثبّت لا يحذف بيانات المدرسة تلقائياً.
لنقل مدرسة إلى حاسبة أخرى: استخدم «نسخ احتياطي كامل ZIP»، وانقل الملف إلى الحاسبة الجديدة ثم اختر «استعادة نسخة ZIP» من إعدادات البرنامج.

الاختبارات
----------
اختبارات قاعدة البيانات: python -m unittest discover -s tests -v
فحص صياغة الكود: python -m py_compile school_manager.py
هذه الاختبارات لا تستبدل تجربة الواجهة بصرياً على Windows ولا اختبار المُثبّت على جهاز نظيف.


إذا فشل البناء (مهم)
--------------------
- لا تعتمد على السطر الأخير [ERROR] وحده؛ هو تنبيه عام فقط.
- الإصدار الحالي من build_windows.bat يكتب جميع تفاصيل الخطأ في build_log.txt داخل مجلد المشروع، ويعرض السجل عند الفشل.
- أرسل ملف build_log.txt كاملًا للدعم إذا توقف البناء؛ فهو يحدد هل المشكلة من Python أو تنزيل PyInstaller أو بناء EXE أو Inno Setup.
- إذا ظهر تحذير بأن Inno Setup غير موجود لكن تم بناء التطبيق، فهذا يعني أن EXE موجود في dist\SchoolManagerPro\SchoolManagerPro.exe وأن ملف Setup لم يُنشأ بعد. ثبّت Inno Setup 6 ثم أعد تشغيل build_windows.bat.
- عند فشل تنزيل الحزم، تأكد من اتصال الإنترنت وعدم حظر pip بواسطة الشبكة أو برنامج الحماية، ثم أعد تشغيل البناء.

قبل البيع التجاري
-----------------
هذا المشروع هو إصدار أول قابل للبناء، وليس اعتماداً تجارياً نهائياً. قبل البيع الفعلي:
- اختر الاسم التجاري النهائي، وأضف بيانات شركتك والدعم الفني وسياسة الخصوصية وشروط الترخيص.
- لا تضع بيانات حقيقية للطلاب في نسخة العرض. بيانات الطلاب والوثائق معلومات شخصية ويجب حمايتها.
- اختبر تسجيل واستعادة نسخة ZIP على جهازين مختلفين، والطباعة/التصدير، وأحجام بيانات كبيرة.
- أضف نظام تفعيل وتراخيص تجاري إذا تريد ربط كل نسخة بمدرسة أو مدة اشتراك؛ لا يتضمن الإصدار الحالي تفعيل تراخيص مدفوع.
- لا توجد حالياً صلاحيات مفصلة لكل شاشة أو تشفير لملف SQLite نفسه؛ أضف هذه الضوابط إذا كانت مطلوبة لدى المدرسة، ولا تعتبر شاشة الدخول بديلاً عن حماية Windows والنسخ الاحتياطية.
- وقّع ملف المُثبّت رقمياً بشهادة موثوقة عند التوزيع التجاري، واحتفظ بنسخة اختبارية وبنسخ احتياطية من بيانات العملاء.
- راجع المتطلبات القانونية المحلية المتعلقة ببيانات الطلاب وإيصالات الرسوم والسجلات المدرسية.

ملفات المشروع
--------------
school_manager.py          كود البرنامج الرئيسي
updater.py                 فحص وتنزيل التحديثات والتحقق من SHA-256
update_config.json         إعداد مصدر التحديث (يُضبط تلقائياً عند النشر)
scripts\set_release_metadata.py  تحديث رقم الإصدار وربط مستودع GitHub
.github\workflows\release-update.yml  بناء ونشر التحديثات المركزية
school_manager_pro.spec    إعدادات PyInstaller
build_windows.bat          بناء EXE والمُثبّت من Windows
installer\SchoolManagerPro.iss  إعدادات مُثبّت Inno Setup
assets\school_manager.ico  أيقونة البرنامج
requirements-build.txt     أداة البناء فقط
.vscode\                   إعدادات تشغيل وتصحيح في VS Code
tests\                     اختبارات قاعدة البيانات

معلومات الإصدار في خصائص EXE
----------------------------
يستخدم ملف version_info.txt لتضمين اسم المنتج وإصداره في خصائص ملف Windows. حدّثه مع APP_VERSION ونسخة المُثبّت عند إصدار تحديث جديد.


التحديث التلقائي من داخل البرنامج
---------------------------------
- زر «تحديث البرنامج» يفحص أحدث إصدار منشور، ويحمّل ملف التثبيت فقط عند توفر نسخة أحدث.
- يتحقق التطبيق من بصمة SHA-256 قبل تشغيل ملف التثبيت. إذا كانت البصمة ناقصة أو غير مطابقة، يرفض تشغيل الملف.
- يتم فحص وجود تحديث عند بدء البرنامج في الخلفية، مع إمكانية الفحص اليدوي من الزر.
- بيانات المدرسة تبقى في %LOCALAPPDATA%\SchoolManagerPro\SchoolData ولا يزيلها تحديث البرنامج.

إعداد النشر المركزي (مطلوب مرة واحدة)
--------------------------------------
1. أنشئ مستودع GitHub عاماً باسم تختاره، وارفع إليه ملفات مجلد SchoolManagerProject كاملة مع مجلدَي .github وscripts.
2. افتح تبويب Actions في المستودع وفعّل GitHub Actions عند الطلب.
3. اختر سير العمل «Build and publish Madrasati Pro update»، ثم Run workflow.
4. أدخل رقم إصدار جديد بصيغة x.y.z، مثل 1.1.0، ثم شغّل البناء والنشر.
5. سينشئ السير العمل مُثبّت Windows، ويحسب SHA-256، وينشرهما في GitHub Release ويربط اسم المستودع داخل التطبيق تلقائياً.
6. في المرات التالية، عدّل كود المشروع وارفع التعديلات إلى المستودع، ثم شغّل سير العمل برقم إصدار أعلى. ستتعرف النسخ المثبتة مسبقاً على الإصدار من الزر أو عند التشغيل.

مهم جداً:
- تحديث النسخ القديمة التي لم يكن فيها زر التحديث يتطلب تثبيت إصدار الترقية الأول مرة واحدة؛ بعدها لا تحتاج المدارس إلى فك ملفات ZIP يدوياً.
- هذا الإصدار يستخدم GitHub Releases العام للتحديثات؛ لذلك يجب أن يكون المستودع الذي ينشر ملفات التحديث عاماً. لا تضع بيانات الطلبة في مستودع GitHub.
- نشر نسخة جديدة لا يحصل بمجرد الضغط على زر «تحديث البرنامج» داخل نسخة المدرسة؛ هذا الزر يفحص وينزّل تحديثاً منشوراً. نشر تحديث جديد يتم من خلال سير العمل المركزي أعلاه.
- يجب تجربة أول تحديث على جهاز اختبار قبل توزيعه على المدارس.
